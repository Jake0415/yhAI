YHAI 배포/DB 전략 정의서

Vercel + Supabase 기반 배포 아키텍처 | 2026-03-14

전략 요약: Vercel (Next.js 네이티브 배포) + Supabase (DB/Auth/Storage/Realtime 올인원)을 기반으로, 공유 RLS 멀티테넌트에서 시작하여 상위 티어에 전용 프로젝트를 제공하는 배포 전략

1. 핵심 결정사항

D-008: Vercel + Supabase 확정
기존 GCP Cloud Run + Neon 전략에서 사용자 결정에 따라 Vercel + Supabase로 변경. Vercel은 Next.js 개발사로 최적 배포 지원, Supabase는 올인원 BaaS 제공.
D-009: 하이브리드 멀티테넌트
Free/Starter는 공유 Supabase + RLS 격리 (비용 효율), Pro 이상은 전용 Supabase 프로젝트 (완전 격리).
D-010: 배포 방식
MVP: Vercel REST API 파일 인라인 업로드 (Git 불필요). Pro+: GitHub 연동 옵션 (코드 소유권).

7. 리스크 및 대응

주요 리스크:
  • Supabase Scale-to-Zero 미지원 → 공유 RLS로 비용 분산
  • Vercel WebSocket 미지원 → Supabase Realtime / SSE 활용
  • 서울 리전 없음 (Supabase) → 도쿄 리전 + Vercel Edge 캐시
  • 벤더 종속 (Vercel + Supabase) → 표준 기술(PostgreSQL, Prisma, Next.js) 사용으로 이식성 확보
  • RLS 정책 버그 → 표준 템플릿 + 자동 테스트
  • 일일 배포 제한 (Pro: 6,000) → 배포 큐 관리, Enterprise 전환
