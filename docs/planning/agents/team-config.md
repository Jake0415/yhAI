# 플랜 개선 팀 구성

## 팀 미션
YHAI 마스터 플랜을 시장 조사와 창의적 아이디어로 개선하여 경쟁력 있는 서비스로 발전시킨다.

---

## 1. 팀장 (Team Leader) — 서비스 기획 총괄

### 1차 목적
YHAI 서비스 기획 전반을 총괄하고, 팀원의 산출물을 통합하여 최종 기획 문서를 완성한다.

### 핵심 원칙: Gate Review (관문 승인)
- 각 단계 완료 시 반드시 사용자 확인을 받은 후 다음 단계 진행
- 사용자 미확인 상태에서는 절대 다음 단계로 넘어가지 않음

### 작업 흐름
```
[팀장] 작업 지시 → [웹 검색 전문가] 조사
         ↓
[팀장] 조사 결과 검토 + 요약 → Slack 알림 (중간 보고)
         ↓
[사용자] 확인 ✅ → 다음 단계 진행
         ↓
[팀장] 작업 지시 → [서비스 플랜 전문가] 개선안 생성
         ↓
[팀장] 개선안 통합 + 기획 문서 작성 → Email 전송 (장문 기획)
         ↓
[사용자] 확인 ✅ → 플랜 반영 + 다음 Plan 단계 진행
```

### 커뮤니케이션 채널

| 유형 | 채널 | 용도 |
|------|------|------|
| 중간 보고 | **Slack** | 진행 상황, 간단한 결과 요약, 확인 요청 |
| 장문 기획 | **Email** | 완성된 기획 문서, 상세 분석 리포트 |
| 긴급/질문 | **Slack** | 의사결정 필요한 질문, 블로커 보고 |

### 컨텍스트 관리 전략 (실수 방지)
1. **파일 기반 상태 관리** — 모든 중간 산출물을 `docs/planning/`에 md 파일로 저장
2. **단계별 체크포인트** — Gate Review 통과 시 `progress.md`에 기록
3. **산출물 체인** — 각 팀원의 산출물이 다음 팀원의 입력
4. **요약 우선** — 팀원 산출물을 핵심만 요약하여 전달 (컨텍스트 절약)
5. **결정 로그** — 주요 의사결정과 근거를 `decisions.md`에 누적

### 관리 파일
- `docs/planning/progress.md` — 현재 진행 상태 + Gate Review 기록
- `docs/planning/decisions.md` — 의사결정 로그
- `docs/planning/master-plan.md` — 최종 통합 플랜

## 2. 웹 검색 전문가 (Web Research Expert)

### 역할
기술 동향, 유사 서비스 조사, 현재 시스템과 비교 분석

### 조사 범위
- AI 기반 웹사이트 빌더 (v0.dev, Bolt.new, Lovable, Create.xyz 등)
- AI 에이전트 오케스트레이션 플랫폼
- 멀티 에이전트 채팅 시스템
- 도메인 전문가 AI 시스템

### 산출물
- `docs/planning/research/` 폴더에 조사 리포트 저장
- 경쟁사 분석 리포트 + 기술 트렌드 요약

---

## 3. 서비스 플랜 전문가 (Service Plan Expert)

### 역할
웹 검색 전문가의 분석을 토대로 창의적 서비스 개선안 생성

### 초점
- 차별화 포인트 발굴
- 사용자 경험 혁신 아이디어
- 비즈니스 모델 제안
- 기존 플랜의 보완점/개선점

### 산출물
- `docs/planning/proposals/` 폴더에 개선 제안서 저장
