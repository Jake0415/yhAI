## 1. 디자인 원칙

### 원칙 1: 투명성 (Transparency)

AI가 무엇을 하고 있는지, 왜 그렇게 판단했는지를 항상 사용자가 알 수 있어야 한다.

- 전문가 추천 시 추천 이유를 명시한다
- 빌드 중 에이전트의 사고 과정을 실시간으로 공개한다
- 요구사항 추출 시 AI가 근거로 삼은 대화 구간을 링크한다
- 비용이 발생하는 모든 작업에 예상/실제 비용을 표시한다

### 원칙 2: 점진적 공개 (Progressive Disclosure)

사용자의 숙련도와 프로젝트 진행 단계에 따라 정보를 단계적으로 노출한다.

- 초보자: 가이디드 대화, 예시 칩, 간단한 카드 뷰
- 숙련자: 상세 설정, 코드 뷰, 에이전트 직접 제어
- 프로젝트 상태에 따라 탭 가용성을 제한하여 인지 부하를 줄인다 (IA 문서 3.4절 참조)

### 원칙 3: 실시간 피드백 (Real-time Feedback)

모든 AI 작업에 즉각적인 시각적 피드백을 제공한다.

- 채팅 응답: 토큰 단위 스트리밍 렌더링
- 빌드 진행: 실시간 진행률 바 + 활동 로그
- 배포: 파이프라인 각 단계 상태 표시
- 대기 시간이 2초를 초과하면 반드시 스켈레톤/스피너를 표시한다

### 원칙 4: 사용자 주도 제어 (User Agency)

AI가 제안하되, 최종 결정은 항상 사용자가 한다.

- 전문가 추천은 수락/거부 선택이 가능하다
- 요구사항은 사용자가 수정/삭제/재정렬할 수 있다
- 빌드는 일시정지/재개/중단이 가능하다
- 모든 Gate Review 지점에서 사용자 확인을 필수로 한다

### 원칙 5: 접근성 우선 (Accessibility First)

기술 배경이 없는 소상공인(페르소나 3)부터 숙련 개발자(페르소나 2)까지 모두 사용할 수 있어야 한다.

- WCAG 2.1 AA 기준 준수
- 전문 용어에는 툴팁 설명을 제공한다
- 키보드만으로 모든 핵심 기능을 조작할 수 있다
- 다크/라이트 테마를 지원한다

### 2.2 타이포그래피

#### 폰트 패밀리

```
본문/UI:     Pretendard (한글) + Inter (영문/숫자)
             -- 가변 폰트(Variable Font) 사용으로 최적 렌더링
             -- TailwindCSS: font-sans에 매핑

코드/모노:   JetBrains Mono 또는 Geist Mono
             -- 코드 미리보기, 파일 트리, 로그에 사용
             -- TailwindCSS: font-mono에 매핑
```

#### 타입 스케일

```
텍스트 크기 (rem 기준)

display-lg:   3rem     (48px)  -- 랜딩 히어로 타이틀      font-bold     tracking-tight
display:      2.25rem  (36px)  -- 랜딩 섹션 타이틀        font-bold     tracking-tight
h1:           1.875rem (30px)  -- 페이지 타이틀           font-semibold tracking-tight
h2:           1.5rem   (24px)  -- 섹션 타이틀             font-semibold tracking-tight
h3:           1.25rem  (20px)  -- 카드/패널 타이틀        font-semibold
h4:           1.125rem (18px)  -- 서브 헤딩               font-medium
body-lg:      1.125rem (18px)  -- 리드 텍스트             font-normal   leading-relaxed
body:         0.875rem (14px)  -- 기본 본문               font-normal   leading-normal
body-sm:      0.8125rem(13px)  -- 보조 텍스트, 레이블     font-normal
caption:      0.75rem  (12px)  -- 캡션, 타임스탬프        font-normal   text-muted-foreground
code:         0.8125rem(13px)  -- 인라인 코드             font-mono
```

참고: 기본 본문 크기는 14px(0.875rem)로 설정한다. SaaS 대시보드에서 정보 밀도를 높이면서도 가독성을 유지하는 최적 크기이다.

#### 행간 (Line Height)

```
tight:     1.25   -- 제목, 짧은 텍스트
normal:    1.5    -- 본문 기본
relaxed:   1.625  -- 긴 문단, 설명 텍스트
loose:     2.0    -- 채팅 메시지 (읽기 편의)
```

### 2.3 스페이싱/그리드 시스템

#### 스페이싱 스케일

TailwindCSS v4의 4px 기준 스페이싱 시스템을 따른다.

```
0:    0px      -- 없음
0.5:  2px      -- 미세 간격 (아이콘-텍스트 사이)
1:    4px      -- 최소 간격
1.5:  6px      -- 뱃지 내부 패딩
2:    8px      -- 컴팩트 패딩 (칩, 태그)
3:    12px     -- 카드 내부 아이템 간격
4:    16px     -- 카드 내부 패딩, 리스트 아이템 간격
5:    20px     -- 섹션 내부 소간격
6:    24px     -- 카드 패딩 (기본)
8:    32px     -- 섹션 간 간격
10:   40px     -- 큰 섹션 간격
12:   48px     -- 페이지 수직 패딩
16:   64px     -- 랜딩 섹션 간 간격
20:   80px     -- 히어로 섹션 패딩
```

#### 그리드 시스템

```
레이아웃 그리드:
  사이드바 너비:        256px (w-64) -- 접힌 상태: 48px (w-12)
  메인 콘텐츠 최대 너비: 1280px (max-w-7xl)
  기본 거터:            24px (gap-6)

카드 그리드 (대시보드):
  데스크톱(xl+):   4열   grid-cols-4  gap-6
  데스크톱(lg):    3열   grid-cols-3  gap-6
  태블릿(md):      2열   grid-cols-2  gap-4
  모바일(sm):      1열   grid-cols-1  gap-4

3-패널 레이아웃 (미리보기 PJ5):
  파일 트리:       240px (w-60)   -- 접기 가능
  라이브 프리뷰:   flex-1         -- 나머지 공간
  수정 대화:       360px (w-90)   -- 접기 가능
```

## 4. 인터랙션 패턴

### 4.1 채팅 스트리밍 응답

```
트리거:  사용자가 메시지를 전송하면
동작:
  1. 사용자 메시지가 즉시 채팅에 추가된다
  2. 전문가 메시지 영역에 스켈레톤(세 줄 펄스)이 표시된다
  3. SSE로 토큰이 수신되면 한 글자씩 타이핑 효과로 렌더링된다
  4. 마크다운 블록(코드, 리스트 등)은 블록 단위로 렌더링한다
  5. 응답 완료 시 타임스탬프가 표시된다
  6. 여러 전문가가 응답할 경우, 각 전문가의 응답이 순차적으로 나타난다

타이밍:
  스켈레톤 표시:     즉시 (0ms)
  첫 토큰 렌더링:    SSE 수신 즉시
  토큰 간 딜레이:    없음 (수신 즉시 렌더링)
  스크롤:            자동 스크롤 (사용자가 위로 스크롤하면 중단)

시각 효과:
  스트리밍 중:       커서 깜빡임 (블링크)
  완료:              커서 사라짐 + fade-in 타임스탬프
```

### 4.2 전문가 초빙/퇴장 트랜지션

```
초빙 (입장):
  1. 사이드 패널에 전문가 카드가 slide-in (오른쪽에서 왼쪽, 300ms ease-out)
  2. 채팅에 시스템 메시지: "{전문가명}이(가) 대화에 참여했습니다"
  3. 전문가 아바타가 scale-up 애니메이션 (0 -> 1, 200ms spring)
  4. 전문가 색상의 미세한 배경 플래시 (200ms)

퇴장 (나가기):
  1. 사이드 패널에서 전문가 카드가 fade-out + slide-out (300ms)
  2. 채팅에 시스템 메시지: "{전문가명}이(가) 대화에서 나갔습니다"
  3. 대화 내 해당 전문가의 기존 메시지는 유지 (약간 투명도 적용: opacity 0.7)

추가 전문가 선택 모달:
  1. [+] 버튼 클릭 시 Sheet(모바일) 또는 Popover(데스크톱)로 전문가 갤러리 표시
  2. 각 전문가 카드에 도메인, 역할 설명, 현재 대화 관련도 표시
  3. 선택 시 즉시 초빙 트랜지션 실행
```

### 4.3 빌드 진행 애니메이션

```
Phase 진행 바:
  완료 Phase:    채워진 원 (● primary 색상) + 실선 연결
  현재 Phase:    펄스 애니메이션 원 (●● 깜빡임) + 진행 바 애니메이션
  대기 Phase:    빈 원 (○ muted 색상) + 점선 연결

에이전트 카드:
  대기 중:       카드 테두리 muted, 아이콘 회색
  작업 중:       카드 테두리 primary 펄스, 아이콘 색상 활성, 진행률 바 애니메이션
  완료:          카드 테두리 success, 체크 아이콘 scale-in
  에러:          카드 테두리 error, 셰이크 애니메이션 (좌우 흔들림 300ms)

활동 로그:
  새 항목 추가:  slide-down + fade-in (200ms)
  오래된 항목:   자동 스크롤 (최신이 위)
  에러 항목:     error 배경색 + AlertTriangle 아이콘
```

### 4.4 포인트&토크 수정

```
트리거:  미리보기(PJ5)에서 라이브 프리뷰 내 요소를 클릭
동작:
  1. 클릭한 요소에 하이라이트 보더가 표시된다 (primary 색상, 2px dashed)
  2. 수정 대화 패널이 활성화된다
  3. 선택된 요소 정보(태그, 클래스, 내용 미리보기)가 표시된다
  4. 사용자가 자연어로 수정 지시를 입력한다
     예: "이 버튼 색상을 파란색으로 바꿔주세요"
  5. AI가 수정을 적용하고, 라이브 프리뷰에 즉시 반영된다
  6. 변경된 파일이 파일 트리에서 뱃지(수정됨)로 표시된다

시각 효과:
  요소 선택:      outline 2px dashed primary + 약간의 scale-up (1.02x)
  수정 적용 중:   선택 요소에 shimmer 효과 (로딩)
  수정 완료:      success 보더 flash → 원래 상태로 복귀
```

### 4.5 드래그&드롭 (요구사항 우선순위)

```
트리거:  요구사항 카드의 드래그 핸들(GripVertical 아이콘)을 잡고 드래그
동작:
  1. 드래그 시작: 카드가 살짝 위로 떠오름 (shadow-lg, scale 1.02, opacity 0.9)
  2. 드래그 중: 드롭 가능 위치에 점선 가이드라인 표시
  3. 카테고리(필수/권장/선택) 사이로 이동 시 카테고리 섹션 하이라이트
  4. 드롭: 카드가 새 위치에 안착 (spring 애니메이션)
  5. 순서 변경이 서버에 자동 저장 (debounced 500ms)

접근성:
  키보드: Space로 선택 → 화살표로 이동 → Space로 드롭
  스크린 리더: 드래그 시작/이동/완료 아나운스먼트
```

```
  +----------------------------------------------+
  3-패널 → 탭 전환
```

## 6. 접근성 가이드

### 6.1 WCAG 2.1 AA 준수 항목

| 기준 | 항목 | YHAI 적용 |
|------|------|-----------|
| 1.1.1 | 비텍스트 콘텐츠 | 모든 아이콘에 aria-label 또는 sr-only 텍스트 제공 |
| 1.3.1 | 정보와 관계 | 제목 계층 (h1-h4) 올바르게 사용, 폼 필드에 label 연결 |
| 1.4.1 | 색상만으로 정보 전달 금지 | 전문가 구분 시 색상 + 아이콘 + 이름 병행. 상태 뱃지에 텍스트 포함 |
| 1.4.3 | 최소 대비 비율 | 본문 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상 |
| 1.4.11 | 비텍스트 대비 | UI 컴포넌트 보더 3:1 이상 |
| 2.1.1 | 키보드 접근 | 모든 인터랙티브 요소에 키보드 접근 가능 |
| 2.4.3 | 포커스 순서 | 논리적인 탭 순서 보장 |
| 2.4.7 | 포커스 표시 | 포커스 링 (outline: 2px solid primary-300, offset 2px) |
| 4.1.2 | 이름, 역할, 값 | ARIA 속성 적절히 사용 |

### 6.2 키보드 네비게이션

```
전역 단축키:
  Cmd/Ctrl + K        -- 글로벌 검색/명령 팔레트
  Cmd/Ctrl + /        -- 사이드바 토글
  Cmd/Ctrl + Enter    -- 메시지 전송 (채팅)
  Escape              -- 다이얼로그/Sheet 닫기

채팅 화면:
  Tab                 -- 예시 칩 간 이동
  Enter               -- 예시 칩 선택
  Shift + Tab         -- 전문가 패널로 이동

요구사항 화면:
  Space               -- 드래그&드롭 모드 시작
  Arrow Up/Down       -- 아이템 이동
  Space               -- 아이템 드롭
  Enter               -- 카드 상세 보기

미리보기 화면:
  Ctrl + 1/2/3        -- 파일 트리 / 프리뷰 / 수정 대화 패널 전환
  Tab                 -- 프리뷰 내 포커스 가능한 요소 간 이동

포커스 트랩:
  다이얼로그, Sheet가 열린 동안 포커스가 내부에 갇힌다 (Radix UI 기본 동작)
```

### 6.3 스크린 리더 지원

```
ARIA 라이브 리전:
  채팅 메시지 영역:      aria-live="polite" role="log"
  빌드 활동 로그:        aria-live="polite" role="log"
  진행률 바:             role="progressbar" aria-valuenow, aria-valuemin, aria-valuemax
  비용 카운터:           aria-live="off" (수동으로 확인 가능하게, 자동 알림 방지)
  에러/경고 알림:        aria-live="assertive" role="alert"

전문가 메시지 구분:
  각 메시지 블록:        aria-label="{전문가명}의 메시지"
  전문가 상태:           aria-label="{전문가명}, {도메인}, 현재 활성"

프로젝트 상태:
  상태 뱃지:             aria-label="프로젝트 상태: {상태명}"
  탭 가용성:             aria-disabled="true" + title="이 단계에서는 사용할 수 없습니다"
```

### 6.4 색상 대비

```
라이트 모드 대비 비율 (foreground / background):
  본문 텍스트:           #0F172A / #FFFFFF = 15.4:1  (AA 통과)
  보조 텍스트:           #64748B / #FFFFFF = 4.6:1   (AA 통과)
  플레이스홀더:          #94A3B8 / #FFFFFF = 3.0:1   (대형 텍스트만 AA)
  Primary CTA:          #FFFFFF / #6366F1 = 4.6:1   (AA 통과)
  Success 뱃지:         #15803D / #DCFCE7 = 4.8:1   (AA 통과)
  Error 뱃지:           #B91C1C / #FEE2E2 = 5.1:1   (AA 통과)

다크 모드 대비 비율:
  본문 텍스트:           #F8FAFC / #0F172A = 15.4:1  (AA 통과)
  보조 텍스트:           #94A3B8 / #0F172A = 4.5:1   (AA 통과)
  카드 텍스트:           #F1F5F9 / #1E293B = 10.5:1  (AA 통과)

전문가 색상 접근성:
  모든 전문가 색상은 흰색 배경(라이트) 또는 어두운 배경(다크)에서
  아이콘/텍스트로 사용 시 최소 3:1 대비를 충족한다.
  메시지 구분은 왼쪽 보더(3px) + 전문가 이름 텍스트로 이중 구분하여
  색맹 사용자도 구분할 수 있도록 한다.
```

## 7. 컴포넌트 상태 정의

주요 커스텀 컴포넌트의 상태를 정의한다. shadcn/ui 기본 컴포넌트의 상태는 라이브러리 기본을 따른다.

### 7.1 프로젝트 카드 (D1)

```
상태:
  기본:        shadow-sm, 보더 border
  호버:        shadow, 보더 border 유지, 배경 약간 밝게
  포커스:      focus ring (primary-300)
  로딩:        Skeleton (카드 전체)

내부 상태별 뱃지 색상:
  CHATTING:              blue Badge
  REQUIREMENTS_REVIEW:   violet Badge
  TEAM_PLANNING:         orange Badge
  BUILDING:              yellow Badge + 로딩 스피너
  BUILD_COMPLETE:        green Badge
  DEPLOYED:              green Badge (filled)
  ARCHIVED:              gray Badge
```

### 7.2 전문가 메시지 버블 (PJ1)

```
구조:
  ┌─ 전문가 아바타 + 이름 + 도메인 태그 ────────────────┐
  │ ▎ (왼쪽 3px 액센트 보더, 전문가 색상)                 │
  │ ▎ 메시지 내용 (마크다운 렌더링)                       │
  │ ▎                                     타임스탬프    │
  └──────────────────────────────────────────────────┘

사용자 메시지:
  우측 정렬, primary-50 배경, 왼쪽 액센트 없음

시스템 메시지:
  중앙 정렬, muted 배경, 작은 텍스트, Separator 스타일
```

### 7.3 에이전트 상태 카드 (PJ4)

```
구조:
  +-------------------+
  | [아이콘] 에이전트명 |
  | [모델] [역할]      |
  | ■■■□□ 60%         |
  | [상태 뱃지]        |
  | 현재 작업 설명      |
  +-------------------+

상태별 스타일:
  대기:     보더 muted, 아이콘 gray, 배경 기본
  작업 중:  보더 primary (pulse), 아이콘 primary, 진행률 바 표시
  완료:     보더 success, 아이콘 success, CheckCircle 표시
  에러:     보더 error, 아이콘 error, 셰이크 + AlertTriangle 표시
```

## 8. 모션/애니메이션 가이드

### 8.1 기본 원칙

```
1. 의미 있는 모션만 사용한다 (장식적 애니메이션 최소화)
2. 200-300ms 범위를 기본으로 한다
3. prefers-reduced-motion 미디어 쿼리를 존중한다
4. ease-out을 기본 이징으로 사용한다
```

### 8.2 트랜지션 토큰

```
duration:
  instant:   0ms       -- 색상 변경 등 즉각 반응
  fast:      100ms     -- 호버 효과, 토글
  normal:    200ms     -- 페이드, 슬라이드
  slow:      300ms     -- 패널 열기/닫기, 모달
  slower:    500ms     -- 페이지 전환, 대형 패널

easing:
  default:   ease-out              -- 대부분의 트랜지션
  enter:     cubic-bezier(0, 0, 0.2, 1)   -- 요소 등장
  exit:      cubic-bezier(0.4, 0, 1, 1)   -- 요소 퇴장
  spring:    cubic-bezier(0.34, 1.56, 0.64, 1)  -- 바운스 효과 (전문가 입장 등)

prefers-reduced-motion:
  모든 duration을 0ms로 설정
  스트리밍 타이핑 효과는 즉시 전체 표시
  Phase 펄스 애니메이션 비활성화
```
