## 요약 (Executive Summary)

YHAI의 현재 요금제($0/$20/$50)는 시장 경쟁력 확보에 유리하나, **단위 경제성(Unit Economics) 관점에서 심각한 구조적 리스크**를 내포하고 있다. AI API 비용이 매출의 40~60%를 차지할 수 있어, 전통 SaaS 대비 낮은 마진(55~70% vs 78~85%)이 불가피하다.

핵심 권고사항:
1. **요금제를 $0/$25/$60 + 크레딧 종량제 하이브리드로 조정** -- 경쟁사 대비 경쟁력 유지하면서 마진 확보
2. **빌드당 토큰 예산제 도입** -- Free 사용자의 비용 통제와 유료 전환 유도
3. **크레딧 추가 구매 모델** -- 구독 외 추가 수익원 확보
4. **12개월 BEP 달성 조건**: 유료 사용자 80명(Pro 60 + Business 20) 또는 MRR $2,600 이상

## 1. 요금제 적정성 분석

### 1.1 경쟁사 요금제 비교 (2026년 3월 기준)

| 플랫폼 | Free | 기본 유료 | 상위 유료 | 팀/비즈니스 | 과금 모델 | ARR |
|--------|------|----------|----------|------------|----------|-----|
| **YHAI (현재)** | $0 (5빌드/월) | $20/월 (50빌드) | $50/월 (무제한) | - | 구독 | - |
| **Bolt.new** | $0 (1M 토큰) | $25/월 (10M 토큰) | $50~$200/월 | $30/인/월 | 토큰 종량 | $40M |
| **Lovable** | 5크레딧/일 | $25/월 (100크레딧) | $50/월 (더 많은 크레딧) | Enterprise 커스텀 | 크레딧 종량 | $300M |
| **v0.dev** | $5 크레딧/월 | $20/월 ($20 크레딧) | $30/인/월 (팀) | $100/인/월 | 토큰 크레딧 | - |
| **Cursor** | 제한적 무료 | $20/월 ($20 크레딧 풀) | $200/월 (Ultra) | $40/인/월 | 크레딧 풀 | $1B+ |
| **Replit** | 일일 크레딧 | $20/월 ($25 크레딧) | $100/월 (15인) | Enterprise 커스텀 | 노력 기반 종량 | $253M |

#### 핵심 관찰

1. **시장 표준가격대**: 기본 유료 $20~$25/월이 업계 표준. YHAI의 $20/월은 적절한 수준
2. **종량제 전환 추세**: 모든 주요 경쟁사가 **순수 구독에서 크레딧/토큰 기반 종량제로 전환** 완료
3. **YHAI의 구조적 차이**: "빌드 횟수" 기반 과금은 경쟁사의 "토큰/크레딧" 기반과 다름
4. **상위 티어 가격 격차**: 경쟁사의 상위 플랜은 $100~$200까지 존재. YHAI $50은 상대적으로 낮음

### 1.2 Free 플랜 적정성 분석

**현재 Free 플랜**: 2개 프로젝트, 5회/월 빌드, 에이전트 2명, 스테이징만

| 평가 항목 | 현재 상태 | 평가 | 개선 방향 |
|----------|----------|------|----------|
| 프로젝트 제한 | 2개 | 적절 | 유지 |
| 빌드 횟수 | 5회/월 | **너무 관대** | 3회/월로 축소 or 빌드당 토큰 상한 설정 |
| 에이전트 팀 크기 | 최대 2명 | 적절 | 유지 |
| 배포 | 스테이징만 | 적절 | 유지 (Lovable은 배지 필수, 유사 전략 가능) |
| 전환 유인 | 빌드 횟수 제한 | **약함** | 빌드 품질 차이(에이전트 수)를 체감시켜야 함 |

**문제점**: 빌드 1회당 AI API 비용이 $0.50~$3.00 발생하므로, Free 사용자 5회 빌드 시 $2.50~$15.00의 원가가 발생한다. 전환 없이 반복 사용하는 Free 유저는 심각한 비용 부담이 된다.

**권고**: Free 빌드를 3회/월로 축소하고, 빌드당 토큰 상한(예: 500K 토큰)을 설정하여 비용 상한을 관리한다. 또한 Free 프로젝트에 "YHAI로 제작" 배지를 필수 표시하여 바이럴 효과를 확보한다.

### 1.3 Pro/Business 간 차별화 분석

**현재 격차**: $20 vs $50 (2.5배)

| 차별 요소 | Pro ($20) | Business ($50) | 격차 평가 |
|----------|----------|---------------|----------|
| 빌드 횟수 | 50회/월 | 무제한 | 실질적으로 50회면 충분 -- 차별 약함 |
| 에이전트 팀 | 최대 5명 | 최대 5명 + 우선 큐 | "우선 큐"는 체감 어려움 |
| DB | 공유 RLS | 전용 Supabase | **핵심 차별점** (원가 차이 $25/월) |
| 배포 | 스테이징+프로덕션 | + 커스텀 도메인 | 적절 |
| 지원 | 이메일 | 우선 지원 | 1인 운영 시 실행 어려움 |

**문제점**:
- Pro에서 Business로 전환할 유인이 "전용 DB + 커스텀 도메인"뿐이며, $30 추가 비용 대비 체감 가치가 부족
- Pro 50빌드/월은 대부분 사용자에게 사실상 무제한과 동일 -- Business 전환 동기 부재
- Business의 전용 Supabase 원가가 $25/월이므로, $50 가격에서 마진이 얇음

**권고**:
- Pro를 $25/월로 인상 (경쟁사 Bolt, Lovable의 기본 유료와 동일)
- Business를 $60/월로 인상하고, 차별 요소를 강화:
  - 에이전트 팀 최대 8명
  - 우선 빌드 큐 + 프리미엄 모델(Opus) 사용 옵션
  - GitHub 연동 코드 소유권
  - 월간 빌드 리포트
- Enterprise 티어($150+/월) 신설 검토: 전용 인프라 + SLA + SSO

### 2.3 수익성 확보를 위한 구조 전환: 하이브리드 모델

경쟁사들이 채택한 "구독 + 크레딧 종량제" 하이브리드 모델을 적용해야 한다.

#### 제안: 포함 크레딧 + 추가 구매 모델

| 항목 | Free | Pro ($25) | Business ($60) |
|------|------|----------|---------------|
| 포함 크레딧 | 30/월 | 200/월 | 500/월 |
| 추가 크레딧 구매 | 불가 | $10/100크레딧 | $10/100크레딧 |
| 1크레딧 = | ~50K 토큰 | ~50K 토큰 | ~50K 토큰 |
| 크레딧당 원가 | ~$0.15 | ~$0.15 | ~$0.15 |
| 크레딧당 매출 (추가 구매) | - | $0.10 | $0.10 |

> 1크레딧 = 약 50K 토큰이면, 평균 빌드 1회에 약 10~15크레딧 소모.
> Free 사용자: 30크레딧으로 약 2~3회 빌드 가능 (적절한 전환 유인)
> Pro 사용자: 200크레딧으로 약 13~20회 빌드 + 추가 구매 가능

**이 모델의 마진 분석**:

| 항목 | Free | Pro ($25) | Business ($60) |
|------|------|----------|---------------|
| 포함 크레딧 원가 | $4.50 | $30.00 | $75.00 |
| 인프라 비용 | $0.50 | $2.00 | $28.00 |
| **총 원가** | **$5.00** | **$32.00** | **$103.00** |
| **구독 마진** | **-$5.00** | **-$7.00** | **-$43.00** |
| 예상 추가 크레딧 매출 | $0 | $15~$30 | $20~$50 |
| **총 매출 (구독+추가)** | $0 | **$40~$55** | **$80~$110** |
| **조정 마진** | -$5.00 | **$8~$23** | **-$23~$7** |
| **조정 마진율** | -inf | **20~42%** | **-29%~6%** |

Pro 티어에서 추가 크레딧 구매를 유도하면 20~42% 마진이 가능하다. Business 티어는 전용 Supabase 비용($25/월) 때문에 마진이 얇으므로, 가격을 $80~$100으로 인상하거나 전용 DB를 선택 옵션으로 만들어야 한다.

## 3. 수익 다각화 방안

### 3.1 크레딧/토큰 종량제 (최우선)

위 2.3에서 상세 분석한 하이브리드 모델. 경쟁사 전원이 채택한 검증된 모델이다.

**구현 우선순위: P0 (MVP부터 적용)**

- 크레딧 시스템 설계 및 과금 엔진 구현
- Stripe Metered Billing 연동
- 크레딧 사용량 대시보드

### 3.2 프리미엄 에이전트/모델 업그레이드

사용자가 특정 빌드에서 더 높은 품질을 원할 때, 프리미엄 모델(Opus)이나 추가 에이전트를 일회성으로 사용할 수 있는 옵션.

## 5. 리스크와 대응

### 5.1 AI API 비용 상승 리스크

| 리스크 | 확률 | 영향 | 대응 |
|--------|------|------|------|
| Claude API 가격 인상 | 낮음 (가격 하락 추세) | 높음 | 멀티 LLM 전략(Gemini, GPT 대체 가능 설계), 자체 파인튜닝 검토 |
| API Rate Limit 강화 | 중간 | 중간 | 빌드 큐 동시성 관리, 예약 용량(Committed Use) 계약 |
| 특정 모델 단종 | 낮음 | 높음 | 모델 추상화 레이어 -- Sonnet/Opus 교체 가능 설계 |

**긍정적 트렌드**: 2024~2026년 AI API 비용은 지속적으로 하락 중이다.
- Sonnet: $3/$15 (이전 $6/$30 대비 50% 하락)
- Haiku: $1/$5 (이전 $0.25/$1.25 → $1/$5로 세대 교체, 성능 대비 합리적)
- Opus: $5/$25 (이전 $15/$75 대비 67% 하락)

> 현재 PRD에 기재된 Opus $15/$75는 이전 세대 가격이다. **최신 Opus 4.6 가격은 $5/$25**으로 크게 하락했다. 이는 YHAI의 수익성에 매우 긍정적이다.

**업데이트된 빌드 비용 (최신 가격 반영)**:

| 단계 | 모델 | 비용/회 (PRD 기재) | 비용/회 (최신 가격) | 차이 |
|------|------|-----------------|-------------------|------|
| PM 분석 (L1) | Opus 4.6 | $2.10 (추정) | **$0.70** | -67% |
| 에이전트 코드 생성 (L2) | Sonnet 4.6 | $1.95 | **$1.95** | 동일 |
| 전체 빌드 평균 | - | ~$8.00 | **~$4.07** | -49% |

> **중요 발견**: 최신 Claude API 가격 반영 시, 빌드당 비용이 PRD 추정 대비 약 50% 낮아진다. 이는 수익성 전망을 크게 개선한다.

**예상 효과**: 전체 매출의 15~25% 추가 확보, 마진율 20% 이상 개선

#### TOP 2: 빌드당 비용 통제 시스템 (P0)

**왜 중요한가**: 비용 예측 불가능성이 AI SaaS의 최대 리스크다. 빌드당 토큰 상한 없이는 단일 사용자가 과도한 비용을 발생시킬 수 있다.

**실행 항목**:
- 빌드당 토큰 예산 설정 (플랜별 차등)
- 토큰 소비 실시간 모니터링
- 예산 80% 도달 시 사용자 알림
- 예산 초과 시 빌드 일시정지 + 크레딧 추가 구매 유도

**예상 효과**: Free 사용자 원가 50% 절감, 비용 예측 가능성 확보

#### TOP 3: Free-to-Paid 전환 최적화 (P0~P1)

**왜 중요한가**: 전환율 1%p 개선은 1,000명 기준으로 유료 사용자 10명 추가 = MRR $250~$600 증가를 의미한다.

**실행 항목**:
- 적절한 Free 제한 설정 (3빌드, 30크레딧)
- 첫 가입 보너스 크레딧 (Pro 트라이얼)
- 빌드 3회 완료 시 업그레이드 넛지 UI
- Free/Pro 결과물 비교 데모
- "Made with YHAI" 배지 바이럴 효과

**예상 효과**: 전환율 3% -> 5~6%로 개선

### 6.3 1인 개발자 상황에서의 현실적 수익 목표

#### 현실적 제약

1. **개발 시간**: MVP 출시까지 3~4개월, V1까지 6~8개월
2. **마케팅 예산**: 거의 제로 (오가닉 위주)
3. **운영 부담**: 고객 지원, 버그 수정, 인프라 관리를 혼자 수행
4. **비용 상한**: 월 $200~$300 인프라 비용이 개인 부담 가능 한계

#### 단계별 현실적 목표

| 기간 | 목표 | 핵심 지표 | 비용 예산 |
|------|------|----------|----------|
| **M1~M3** (MVP) | 제품 출시 + 초기 사용자 확보 | 총 사용자 200~400명, MRR $0~$300 | $200/월 (자비) |
| **M4~M6** (초기 성장) | Product-Market Fit 검증 | 유료 사용자 20~50명, MRR $500~$1,500 | $200~$300/월 (일부 매출 충당) |
| **M7~M9** (성장기) | BEP 달성 | 유료 사용자 60~100명, MRR $2,000~$3,500 | 매출로 충당 |
| **M10~M12** (안정기) | 지속 가능한 수익 | 유료 사용자 100~150명, MRR $3,500~$5,750 | 매출로 충당 + 이익 발생 |

#### 1년차 현실적 손익 예상 (기본 시나리오)

| 항목 | 금액 |
|------|------|
| 12개월 누적 매출 | $20,000~$28,000 |
| 12개월 누적 비용 (인프라+API) | $15,000~$22,000 |
| **순이익** | **$3,000~$6,000** |
| 월평균 순이익 (후반 6개월) | $500~$1,000 |

> **현실적 판단**: YHAI는 1년차에 대규모 수익을 기대하기 어렵다. 그러나 BEP 달성 후 꾸준히 MRR을 쌓으면, 2년차에는 월 $5,000~$10,000 수준의 안정적 수익이 가능하다. 핵심은 **크레딧 기반 과금으로 마진을 확보**하고, **비용 통제를 철저히** 하는 것이다.
