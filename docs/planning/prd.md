## 1. 제품 개요

### 1.1 비전

> 누구나 AI 전문가 팀과 대화하며, 코딩 없이 완성도 높은 웹 서비스를 만들 수 있는 세상

### 1.2 미션

사용자의 아이디어를 AI 도메인 전문가와의 대화를 통해 구체화하고, AI 에이전트 개발팀이 자동으로 풀스택 코드를 생성하여 배포까지 완료하는 올인원 플랫폼을 제공한다.

### 1.3 핵심 가치 제안 (Value Proposition)

| 가치 | 설명 |
|------|------|
| **전문가 기반 요구사항 도출** | 일반 챗봇이 아닌, 도메인 전문가(이커머스, SaaS, 마케팅 등)가 사용자의 맥락에 맞는 질문과 조언을 제공 |
| **멀티 에이전트 자동 빌드** | PM Agent가 프로젝트를 분석하여 동적으로 개발팀을 구성하고, Phase 기반으로 단계적 빌드 수행 |
| **투명한 빌드 과정** | 에이전트의 사고 과정, 비용, 진행률을 실시간으로 공개하여 블랙박스 제거 |
| **코딩 제로 → 배포 완료** | 대화만으로 요구사항 확정부터 Vercel 자동 배포까지 원스톱 제공 |

### 1.4 타겟 사용자

| 페르소나 | 핵심 니즈 | YHAI 솔루션 |
|---------|----------|------------|
| **창업 기획자** (비개발, MVP 검증) | 아이디어를 빠르게 프로토타입으로 구현 | 가이디드 대화 + 유사 사례 카드 + 빠른 배포 |
| **1인 개발자** (보일러플레이트 자동화) | 반복 작업 자동화, 코드 품질 보장 | 코파일럿 빌드 + 사고 과정 투명성 + Git 코드 소유권 |
| **소상공인** (IT 비전문가) | 기술 용어 없이 웹사이트 구축 | 능동적 전문가 가이드 + 예시 칩 + 시각적 미리보기 |

### 1.5 경쟁 포지셔닝

```
                  빌드 품질 (높음)
                      |
           YHAI       |      Cursor
       (전문가 대화 +  |   (개발자 IDE 통합)
        멀티에이전트)   |
                      |
 가이드 수준 ----------+---------- 자유도
 (높음)               |           (높음)
                      |
       Lovable        |      Bolt.new
    (디자인 중심)      |   (빠른 프로토타입)
                      |
                  빌드 품질 (낮음)
```

**YHAI 차별화 포지션**: 높은 가이드 수준 + 높은 빌드 품질

| 경쟁사 | 강점 | YHAI 차별점 |
|--------|------|-----------|
| **Bolt.new** | 속도, 실시간 미리보기 | 도메인 전문가 시스템, 멀티에이전트 팀, 비용 투명성 |
| **Lovable** | 디자인 품질, 직관적 UX | PM Agent 동적 팀 생성, Phase 기반 단계적 빌드, 코파일럿 개입 |
| **v0** | Vercel 생태계, 컴포넌트 품질 | 풀스택(프론트+백+DB) 생성, 자동 배포, 전문가 크로스 레퍼런스 |
| **Cursor** | 개발자 친화, IDE 통합 | 비개발자 접근성, 가이디드 대화, 자동 팀 구성 |

## 2. 기능 요구사항 (MoSCoW 분류)

### 2.1 Must Have -- MVP (최소 기능 제품)

> MVP 목표: 사용자가 AI 전문가와 대화하여 요구사항을 정리하고, AI 에이전트 팀이 코드를 생성하여 배포할 수 있는 end-to-end 흐름 완성

#### F-M01: 회원가입/로그인

| 항목 | 내용 |
|------|------|
| **설명** | Supabase Auth 기반 소셜 OAuth(Google, GitHub, Kakao) + 이메일/비밀번호 인증 |
| **수용 기준** | - 소셜 로그인 3종 중 1종 이상 동작 / - 이메일 회원가입 + 이메일 인증 / - JWT 토큰 자동 갱신 / - 로그인 상태 유지 (세션 관리) |
| **관련 화면** | A1 로그인, A2 회원가입, A3 OAuth 콜백 |
| **API** | `POST /auth/signup`, `POST /auth/login`, `GET /auth/callback`, `GET /auth/me` |

#### F-M02: 프로젝트 생성 (인텐트 캡처)

| 항목 | 내용 |
|------|------|
| **설명** | 사용자가 "무엇을 만들고 싶은지" 자유 입력 -> AI가 인텐트를 분석하여 프로젝트 생성 + 유사 사례 카드 제시 |
| **수용 기준** | - 자유 텍스트 입력으로 프로젝트 생성 / - 유사 서비스 3~5개 카드 표시 / - 카드 선택 시 초기 컨텍스트 강화 / - 프로젝트 상태 `CHATTING`으로 시작 |
| **관련 화면** | D2 새 프로젝트 생성 |
| **API** | `POST /api/projects` |

#### F-M03: 전문가 자동 추천 + 초빙

| 항목 | 내용 |
|------|------|
| **설명** | 사용자의 인텐트/대화 내용을 분석하여 적합한 도메인 전문가를 자동 추천하고, 사용자가 수락/거부 선택 |
| **수용 기준** | - 인텐트 기반 전문가 2~3명 자동 추천 / - 추천 카드 UI(수락/거부 버튼) / - 수락 시 전문가가 대화에 참여 / - 사용자가 직접 전문가 추가/제거 가능 |
| **관련 화면** | PJ1 채팅 (사이드 패널) |
| **API** | `GET /api/experts/recommend`, `POST /api/projects/:id/experts`, `DELETE /api/projects/:id/experts/:expertId` |

#### F-M04: 멀티 전문가 채팅 (스트리밍)

| 항목 | 내용 |
|------|------|
| **설명** | 복수 전문가가 동시에 참여하는 채팅. 각 전문가가 자기 도메인에서 질문/조언 제공. SSE 기반 실시간 스트리밍 |
| **수용 기준** | - 전문가별 아바타/이름/색상 구분 / - SSE 기반 실시간 응답 스트리밍 / - 마크다운 렌더링 / - 예시 칩(빠른 응답) 지원 / - 메시지 히스토리 페이지네이션 |
| **관련 화면** | PJ1 채팅 |
| **API** | `POST /api/projects/:id/conversation/messages` (SSE), `GET /api/projects/:id/conversation/messages` |

#### F-M05: 요구사항 자동 추출 + 확정

| 항목 | 내용 |
|------|------|
| **설명** | 대화 내용에서 AI가 자동으로 요구사항을 추출하여 카드 형태로 정리. 사용자가 검토/수정 후 확정 |
| **수용 기준** | - AI 자동 추출 버튼 / - 요구사항 카드(필수/권장/선택 분류) / - 드래그&드롭 우선순위 재정렬 / - 개별 항목 편집/삭제 / - "요구사항 확정" 클릭 시 상태 `REQUIREMENTS_REVIEW` -> `TEAM_PLANNING` 전환 |
| **관련 화면** | PJ2 요구사항 |
| **API** | `POST /api/projects/:id/requirements/extract`, `GET/POST/PATCH/DELETE /api/projects/:id/requirements`, `POST /api/projects/:id/requirements/confirm` |

#### F-M06: PM Agent 팀 구성 + Phase 분해

| 항목 | 내용 |
|------|------|
| **설명** | PM Agent(Opus)가 확정된 요구사항을 분석하여 최적 팀 구성(3~5명) 제안 + Phase 실행 계획 수립. 사용자 승인 후 빌드 시작 |
| **수용 기준** | - PM 분석 과정 SSE 스트리밍 / - 팀 구성 제안(에이전트 역할, 모델, 비용 예측) / - Phase 계획(순서, 의존성, 예상 시간) / - 사용자가 에이전트 추가/제거 가능 / - "승인" 클릭 시 빌드 시작 |
| **관련 화면** | PJ3 AI 팀 |
| **API** | `POST /api/projects/:id/team/analyze` (SSE), `GET/PATCH /api/projects/:id/team`, `POST /api/projects/:id/team/approve` |

#### F-M07: AI 에이전트 빌드 (실시간 진행상황)

| 항목 | 내용 |
|------|------|
| **설명** | 승인된 팀이 Phase별로 코드를 생성. 실시간으로 에이전트 활동, 진행률, 비용을 표시하는 Mission Control UI |
| **수용 기준** | - Phase 진행 바 / - 에이전트별 진행률 카드 / - 실시간 활동 로그 (Supabase Realtime) / - 빌드 일시정지/재개 / - 에러 발생 시 자동 재시도 + 사용자 알림 |
| **관련 화면** | PJ4 빌드 (Mission Control) |
| **API** | `POST /api/projects/:id/build/start`, `POST /api/projects/:id/build/pause`, `POST /api/projects/:id/build/resume`, `GET /api/projects/:id/build/stream` (SSE) |

#### F-M08: 3-패널 미리보기

| 항목 | 내용 |

## 3. 비기능 요구사항 (NFR)

### 3.1 성능

| 항목 | 목표 | 측정 방법 |
|------|------|----------|
| **채팅 첫 토큰 응답** | < 500ms | SSE 첫 바이트 도착 시간 |
| **채팅 전체 응답** | < 10s (일반 질문) | 마지막 토큰 도착 시간 |
| **빌드 시작 지연** | < 3s (승인 후 첫 에이전트 실행) | 승인 버튼 ~ 첫 활동 로그 |
| **전문가 추천 응답** | < 2s | 인텐트 입력 ~ 추천 카드 표시 |
| **페이지 로드** | LCP < 2.5s, FID < 100ms, CLS < 0.1 | Core Web Vitals |
| **미리보기 로드** | < 5s (프리뷰 iframe 렌더링) | 미리보기 탭 전환 ~ 화면 표시 |
| **배포 완료** | < 5분 (코드 생성 후) | 배포 시작 ~ URL 접근 가능 |

### 3.2 확장성

| 항목 | 초기 (3개월) | 목표 (12개월) |
|------|-------------|-------------|

| **동시 빌드** | 10건 | 100건 |
| **프로젝트 저장** | 사용자당 10개 | 사용자당 50개 |
| **메시지 저장** | 프로젝트당 1,000건 | 프로젝트당 10,000건 |

### 3.3 가용성

| 항목 | 목표 |
|------|------|
| **서비스 가용성** | 99.5% uptime (월간 다운타임 3.6시간 이내) |

| **배포 롤백** | < 5분 (Vercel 즉시 롤백) |

### 3.4 보안

| 항목 | 구현 방법 |
|------|----------|
| **인증** | Supabase Auth (OAuth 2.0 + JWT) |

| **비밀 관리** | 환경변수 -- Vercel/Supabase 비밀 저장소 활용 |
| **입력 검증** | Zod 스키마 기반 서버 사이드 검증 |
| **Rate Limiting** | API별 요청 제한 (인증: 10회/분, 채팅: 30회/분, 빌드: 5회/시간) |

## 4. 기술 제약사항

### 4.1 Claude API 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| **토큰 제한** (200K 컨텍스트) | 장기 대화/복잡한 빌드에서 컨텍스트 초과 가능 | 대화 요약 + 슬라이딩 윈도우, Phase별 컨텍스트 리셋 |
| **API Rate Limit** | 동시 빌드 수 제한 | Celery + Redis 큐로 동시성 관리, 우선순위 큐 |
| **비용** | Opus 호출 비용 높음 ($15/M input, $75/M output) | PM Agent만 Opus, 나머지 Sonnet($3/$15), 도메인 감지는 Haiku($0.25/$1.25) |
| **응답 시간 변동** | 피크 시간대 지연 가능 | 타임아웃 설정 + 재시도 로직 + 사용자 알림 |

### 4.2 Vercel 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| **Serverless 함수 타임아웃** | 45s (Pro) / 300s (Enterprise) | 장시간 작업은 백그라운드 처리 (Celery + Redis), SSE 스트리밍 |
| **빌드 타임아웃** | 45분 | 생성 코드 최적화, 의존성 최소화 |
| **대역폭** | Pro 1TB/월 | 사용자 앱 트래픽 모니터링, CDN 활용 |
| **파일 업로드 크기** | 100MB/배포 | 코드 분할, 불필요 파일 제외 |

### 4.3 Supabase 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| **연결 수** | Free 60개, Pro 200개 | Connection Pooling (PgBouncer) + 공유 RLS 아키텍처 |
| **스토리지** | Free 1GB, Pro 100GB | 코드 아티팩트는 텍스트 위주 (용량 작음) |
| **Realtime 연결** | 500 동시 (Pro) | 프로젝트별 채널 격리, 불필요 구독 해제 |
| **Edge Functions** | 메모리 256MB, 실행 50ms~400s | AI 호출은 FastAPI 백엔드에서 처리 |

### 4.4 솔로 개발자 제약

| 제약 | 영향 | 대응 |
|------|------|------|
| **개발 리소스** | 1인 개발로 개발 속도 제한 | MVP 범위 최소화, Phase별 점진적 확장 |
| **테스트 커버리지** | 전수 테스트 불가 | 핵심 플로우 E2E 테스트 우선, AI QA Agent 활용 |
| **운영 부담** | 24/7 모니터링 불가 | Vercel/Supabase 관리형 서비스 활용, 자동 알림 |
